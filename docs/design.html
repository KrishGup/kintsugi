01

What it is

An agent that turns photos of a broken object into a verified, parametric, printable replacement part. It guides the photos, measures the mating geometry, writes a Part Spec, designs the part in OpenSCAD, checks its own drawings and mesh against that spec, closes the loop with a printed fit coupon, and exports an STL with a print card.

The same machinery is a general OpenSCAD design agent with a real verification loop. Photo-to-part is the hero flow; "design me a bracket with these dimensions" runs through the identical pipeline with the measurement stages skipped.

Principles

Interfaces, not scans

A replacement part is defined by its mating geometry. Measure those few dimensions precisely and design the body freely. This turns "3D-scan the object" (hard, imprecise) into "measure a ring and a height" (tractable, sub-millimeter).

Everything believed is written down

The Part Spec holds every dimension with its estimates, sources and confidence. Interface dimensions must be confirmed before final export, or the export is labeled as unconfirmed.

Checked like an engineer

Drawings, mesh measurements, an interference check against a proxy of the object, and a printed fit coupon. A separate critic reviews the drawings in fresh context and never sees the code.

Parametric output

Every user-facing dimension is a customizer parameter. A near miss is a slider nudge, not another run.

02

End-to-end flow

Nine stages. The user is asked questions in batches at four defined points (intake, measurement confirmation, spec review, concept choice); everything else runs unattended and streams to the UI.

Intake

Photos plus one sentence. Vision pass identifies the object, the broken part, its function, likely interfaces and load direction. One batched question card.

→ intake.json, draft spec.yaml

Guided capture

A shot list with purpose, camera position and a ghost overlay. Calibration by printable ArUco sheet or a coin. Each upload is graded (sharpness, exposure, marker pose, occlusion) with a specific retake instruction.

→ photos/*.jpg + grades

Measurement

Rectify to a true top-down, mm-scaled image and fit circles and outlines. Low-confidence interface dims become measurement request cards.

→ measurements.json, spec estimates

Spec review

Editable spec card: interfaces with target, tolerance, source, status. Interface dims must reach confirmed before final export.

→ spec.yaml (confirmed)

Concepts

Two or three quick renders (match original, reinforced loop, strap with lanyard hole) with one line on strength and printability. Skippable.

→ design_intent

Modeling loop

Write part.scad → compile → blueprint → checks → interference → overlay → critic → revise. Every iteration streams a diff, a sheet, a checks table and a narration line.

→ part.scad, sheets/, checks.json

Review

3D viewer, blueprint tabs, checks table, sliders from customizer annotations, code pane. Chat edits re-enter the loop; every iteration is a commit you can branch from.

→ iteration N+1

Fit test

A coupon of just the mating feature: a tolerance ladder at −0.2 / 0 / +0.2 mm. Print, report which fits, and the clearance is locked.

→ coupon.stl, clearance confirmed

Export

Oriented STL and 3MF, customizer-ready .scad, blueprint PDF, print card with settings and reasons, spec, session log.

→ export/bundle.zip

The Part Spec

The spec is the contract between measurement, modeling and verification. Every dimension keeps its evidence; every interface dimension carries a measure recipe that tells the checker how to measure it on the mesh, so verification is executable rather than interpretive.

part:
  name: bottle_handle
  role: carry handle; ring sits around the neck under the cap flange
  object: 1 L wide-mouth plastic bottle
  design_intent: reinforced loop, finger scallops (concept B)

interfaces:
  - id: neck_ring
    type: cylindrical_bore
    mates_with: bottle neck between cap flange and shoulder
    fit: sliding                 # press | sliding | loose | snap
    clearance: 0.25              # mm; material default, overridden by coupon result
    dims:
      inner_diameter:
        target: 43.2
        tol: 0.3
        status: confirmed        # unknown | estimated | confirmed
        estimates:
          - {value: 43.4, source: rectified_sheet, photo: shot3.jpg, conf: 0.75}
          - {value: 43.2, source: user_caliper, conf: 0.95}
        measure: {recipe: circle_fit_inner, at_z: 3.0}
      height_available:
        target: 6.0
        tol: 0.5
        status: estimated
        estimates:
          - {value: 6.2, source: jig_side_view, conf: 0.6}
        measure: {recipe: extent_z, feature: ring}

requirements:
  - id: load
    text: carry a 1.5 kg full bottle by two fingers, with margin
    derived:
      loop_inner_width: {min: 40}
      loop_inner_height: {min: 25}
      min_cross_section: {min: [6, 4]}
  - id: cap_clearance
    text: cap must thread on and off with the ring in place

context:                         # proxy geometry for interference checks
  - {id: neck,       shape: cylinder, d: 43.2, h: 12, at: [0, 0, 0]}
  - {id: cap_flange, shape: cylinder, d: 62,   h: 3,  at: [0, 0, 6]}
  - {id: shoulder,   shape: cone, d1: 43.2, d2: 85, h: 10, at: [0, 0, -10]}

print: {material: PETG, nozzle: 0.4, min_wall: 1.6, orientation_hint: ring flat on bed}

Evidence is never overwritten

New measurements append to estimates. The fusion rule picks the target; the history stays visible on the spec card.

Status gates export

confirmed means user-confirmed, or two independent high-confidence sources agreeing within tolerance. Anything else exports with a "fit unconfirmed, print a coupon first" label.

Context is deliberately crude

Cylinders and cones are enough to compute interference volume and to draw the part around a ghost of the object on the assembly view.

Fusion rule

  • Trust order per dimension: user-confirmed manual › two rectified-sheet shots agreeing › one rectified shot › reference object › reconstruction-derived.
  • Disagreement beyond tolerance produces a measurement request card, never a silent average.
  • Interface dims need confidence ≥ 0.9 or user confirmation; body dims ≥ 0.6.

Convergence policy

  • Iteration budget per phase: six. Compile errors have their own short loop and do not consume the budget.
  • Oscillation: a dimension crossing its target twice freezes that parameter and asks the user.
  • Same failure twice in a row switches the modeling strategy (CSG → template → profile) before asking.
  • Ask only for: interface dims below threshold, source disagreement beyond tolerance, ambiguous function, or export with unconfirmed dims. Questions are batched.

Modeling strategies

Spec-driven CSG (default)

Primitives plus BOSL2 for rounding, attachments, threads and joiners. Handles, brackets, hooks, knobs, caps.

Profile-based

polygon() from a traced outline with linear_extrude or rotate_extrude. Exact outlines, almost no modeling risk.

Template catalog

Vetted parametric templates with named parameters, docstrings, default print settings and self-check modules: ring-and-loop handle, snap clip, threaded cap, D-shaft knob, L-bracket, hook, hinge pin, spacer, battery door, buckle. The demo's safety net.

Tournament

First pass runs two or three strategies in parallel; checks plus critic pick the survivor. For ambiguous part classes.

07

Agent runtime

The designer runs on the agent SDK, which is the same agent loop as the coding assistant, given a working directory (the session workspace) and a tool set. The reliable path is the typed tools; a Python shell with OpenCV, trimesh and numpy is the escape hatch for the cases the tools do not cover.

GroupToolsNotes
Perceptionanalyze_photo · grade_capture · detect_reference · rectify · segment · measure_planar · fit_primitiveReturn numbers with confidence, plus annotated images for the UI
Specwrite_spec · update_spec · request_measurement · request_photoRequests become cards; the run pauses on them
Modelingscad_compile · render_blueprint · mesh_checks · interference_check · overlay_compare · printability · generate_coupon · critiqueEvery call writes to the workspace and emits an SSE event
Deliveryexport_bundleOrientation pass, 3MF, PDF sheet, print card

Control policy

  • Plan first: a short strategy card (measurement approaches, modeling strategy, which checks matter) before any photo is processed. Shown to the user, editable.
  • Model roles are separate calls: intake vision, spec writer, designer, critic. All use the strongest available vision-capable model; the provider layer is swappable and disclosed in the submission.
  • Prompts carry the engineering conventions: origin at the primary interface, Z up, bed at z = 0, customizer annotations for every user-facing parameter, assert() on spec constraints, minimum walls of two perimeters, fillets at stress concentrations, orientation chosen against the load.

Evaluation

Three layers. Unit tests pin the toolchain to known geometry. A benchmark measures the loop from typed specs, with no photos in the way. An A/B study compares what the agent designs against what people designed for the same repair.

Toolchain unit tests

Cylinders, boxes, rings and a stepped gauge block with known dimensions. The blueprint's measured dimensions must land within 0.05 mm of the truth; wall thickness, overhang and interference checks must agree with analytic values.

Measurement tests

Synthetic photos of the calibration sheet rendered under a pinhole camera at 0–35° tilt, with circles and rectangles of known size drawn on the sheet plane. After rectification, diameters must be within 0.5 mm; the coin-reference path within 3 %.

Loop benchmark

The bottle handle plus household parts from typed specs. Metrics: interface dimension error, iterations to converge, critic agreement with a human reviewer, failures per strategy.

A/B vs human designs

Open-source OpenSCAD repair parts with known parameters. Derive a spec from each, hide the source, let the agent design to the spec, then compare: key dimensions, volume, silhouette IoU per view, Chamfer distance between meshes, and a blind critic preference.

Build plan and repository layout

  1. Toolchain first: compile wrapper, software renderer, blueprint sheet, mesh checks. Tested on primitives and on the existing handle design.
  2. Spec model and the loop from typed dimensions, no photos. This isolates the loop and gets the handle converging from a spec.
  3. Critic, context proxy, interference, coupons.
  4. Measurement core: sheet generator, marker detection, rectification, planar measurement, reference objects, capture grading, synthetic tests.
  5. Intake and capture planning; measurement fusion into the spec.
  6. API server and UI.
  7. Benchmark, A/B study, tuning.
  8. README, CI, hand-off.

Runtime notes

OpenSCAD
Headless CLI for STL export; PNG renders through xvfb when needed. Templates avoid features newer than 2021.01 so the stable release works; a Manifold-enabled snapshot speeds up BOSL2-heavy models.
Rendering
A numpy z-buffer rasterizer for orthographic views gives exact mm-per-pixel and full control of annotations. OpenSCAD's own renders remain an option for the drawing-style experiment.
Booleans
manifold3d through trimesh for interference volumes and coupon generation.
Vision
OpenCV ArUco for markers, pose and rectification; the model for semantic reads (what is this, is the feature occluded).
Agent
agent SDK; designer and critic as separate sessions; provider abstraction so the model can be swapped and disclosed.
Licensing
OpenSCAD and BOSL2 are disclosed in the submission; an in-browser WASM preview, if shipped, follows the GPL.
